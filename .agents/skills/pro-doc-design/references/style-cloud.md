# style: "cloud"：濃紺の帯 × 淡い青の面 × 白いカード

ユーザーが「このデザインめっちゃいい」と気に入った見た目。IT・クラウド・AI・業務紹介の資料はまずこれを使う。
Material Design 3 の考え方（色の面の上に白いカードを浮かせる・角丸・文字サイズの差をはっきり）に、
表紙と同じ「雲・回路・ドット」のモチーフを全ページで繰り返して統一感を出す。

- 見本：`examples/sample_cloud.js`（A4横・5ページ。複製して書き換える）
- 部品：`deck_kit.js` の `style: "cloud"`（下の「部品」）、背景のイラスト：`scripts/cloud_art.js`

```js
const d = kit.createDeck({ size: "A4", style: "cloud", footer: "資料名", title: "資料名" });
await d.cloudCover({ eyebrow: "AI × AWS ｜ LEARNING REPORT", title: ["AWS SAP", "壁打ちレポート"], subtitle: [...], presenter: "【所属】【氏名】", motif: "chat" });
const s = await d.page("本題", "04 ｜ METHOD", "やり方", "問題集で範囲を押さえ、分からない所はAIとの壁打ちで深めた");
d.card(s, d.M, d.TOP, 5, 3, d.C.background1, "hero card");   // 本文は d.TOP(2.1)〜d.BOTTOM(7.5)
```

## ページの骨組み（A4横 11.69×8.27 インチ）

| 位置（y） | 要素 | 中身のルール |
|---|---|---|
| 0〜1.31 | 濃紺の帯（グラデーション＋回路の線＋小さな雲） | 背景画像。マスター `BAND` |
| 0.2 | アイブロウ（シアン・11pt・字間3） | `"04 ｜ METHOD"`：ページ番号＋英字の短いラベル |
| 0.52 | 帯のタイトル（白・24pt・太字） | **目次の項目名と同じにする**（例：「やり方」）。文にしない |
| 1.46〜1.96 | POINT の帯（白いカード＋オレンジの「POINT」） | **このページで伝えたいことを1文で**（16pt太字・40字前後まで） |
| 2.1〜7.5 | 本文 | 白いカードで組む。外周の余白0.5、カードの間隔0.25 |
| 7.85 | フッター（資料名・ページ番号、9pt灰色） | マスターが入れる |

- 帯のタイトル＝目次の名前、POINT＝結論の文。結論タイトル（アクションタイトル）の役目は POINT が持つ。
- POINT と本文で同じ文を書かない（`redundancy_check.py` で確かめる）。本文は根拠・中身だけ。
- 目次（2ページ目）にも POINT を置き、全体の流れを1文で言う（例：「導入 → 本題 → まとめ」の3部構成）。

## 文字
- 和文 Noto Sans JP、英数字 Inter（どちらも Google の無料書体）。PDF には埋め込まれる。pptx を編集する PC には入れてもらう。
- 大きさの段（はっきり差を付ける）：表紙タイトル 64/54 → 帯タイトル 24 → 主役の数字 44〜88 → カードの見出し 15〜22 → POINT 16 → 本文 13〜17 → 注記 11〜12。
- 主役の数字は「数字だけ大きく、単位は半分以下」（例：`71` 88pt ＋ `%` 40pt）。
- Noto Sans JP は BIZ UDPゴシックより字幅も行の高さも大きい。表は 12pt・内側の余白 `[0.02, 0.1, 0.02, 0.1]`・2行の行は 0.57 インチが目安。必ず実際に書き出して、表が下にはみ出していないか見る。

## 部品（`style: "cloud"` で使えるもの）

| 部品 | 使い方 |
|---|---|
| `await d.cloudCover({eyebrow, title:[2行], subtitle, presenter, motif})` | 表紙。副題は runs で、数字か要点を1つだけオレンジ・大きく |
| `await d.page(section, eyebrow, title, point)` | 本文ページ（帯＋POINT）。戻り値はスライド |
| `d.toc(s, groups, {rowH, gap, groupGap})` | 目次。部ごとに色の付いた縦長ラベル＋白い行カード（番号・項目名・説明） |
| `d.card(s, x, y, w, h, fill, name, {flat, r, line})` | 角丸カード。白は影付き、濃紺は影なし（角に筋が出るため） |
| `d.pill(s, x, y, w, text, fill, color, name, size, h)` | 丸いラベル（「最大の特徴」「型1」「→ P.5」など） |
| `await d.closingArt(s, {y, h, text, accent, sub, motif, inline, crop})` | 締めの帯。表紙の絵を**比率を保ったまま**切り抜いて敷く |
| 既存の型（`table` `chips` `timelineBar` `flowRows` `steps` `cards` `stat` `callout` `roadmap`） | そのまま使える。cloud では下地が白いカードになり、表は白で塗られる |

- `motif`：`"chat"`（吹き出し：AI・相談・対話）／`"ops"`（監視画面＋チェック＋ベル：運用・業務）／`"none"`。表紙と締めの帯で同じものを使う。
- 締めの帯：高さ1.8前後なら `text` と `accent`（2行目オレンジ）＋氏名。高さ0.9前後なら `inline: true, crop: "bottom"`（回路の線だけの所を切り抜く。モチーフが途中で切れると見苦しい）。
- 画像は `sizing: crop` で切り抜く。`w` と `h` を元の比率から変えて縮めると絵がゆがむ（実際に指摘された）。

## ページの組み方（視線の流れ）
1. 主役を1つ決め、左上に一番大きく置く（例：「71%」の白いカード、1位の淡いオレンジのカード）。
2. 右上に補助（基本の数字など）、下段に根拠（グラフ・実例）、右下に「分析」の濃紺カード（Z字の終点）。
3. 比べるときは、相手を灰色で小さく・控えめに、主役を白＋オレンジの見出しで大きくする。
4. 手順は横並びのカード＋矢印。一番大事な工程だけ色を付け、▲ の注記で理由を書く。
5. くり返しは破線の戻り矢印（「腹落ちするまで、くり返す」）。
6. 白いカードの中にさらに白いカードを入れない。入れ子にするときは中を淡い色（`#F3F7FB` など）にするか、外側をやめて見出しだけにする。

## よくある失敗（このスタイルで実際に起きたもの）
| 症状 | 直し方 |
|---|---|
| 帯のタイトルが長くて帯からはみ出す | 帯は目次の名前だけ。結論は POINT に書く |
| 表が下にはみ出してフッターに重なる | Noto の行の高さで計算し直す（上の「文字」）。行を減らすか12ptに |
| 表の下に大きな空き | 行の高さを足して下端（7.2〜7.5）までそろえる |
| 濃紺のカードの左下に黒い筋 | 濃紺のカードは影なし（`d.card` は自動で外す） |
| 締めの帯の絵が横に伸びる・モチーフが半分で切れる | `closingArt` を使う。低い帯は `crop: "bottom"` |
| カードの説明が3行になってはみ出す | `\n` で2行に収まる言い方にする（Noto は字幅が広い） |
