# 資料の作り方の比較と、このスキルの進め方

## 調べた作り方

| 作り方 | 良い点 | 弱い点 |
|---|---|---|
| **HTMLで作ってPPTXに変換**（Marp、Slidev など） | 見た目の調整が速く、ブラウザですぐ見られる | 通常のPPTX書き出しは**ページが画像**になり、後から文字を直せない。Marp の編集可能な書き出し（`--pptx-editable`）は実験的で、複雑なデザインでは崩れたりノートが消えたりする |
| **PowerPointの図形として直接生成**（pptxgenjs、python-pptx） | 文字・表・図形がすべて**編集できる**。テーマ・レイアウト・アニメーションも扱える | 座標を自分で決める必要がある。プレビューは画像化して確認する |
| **テンプレートを複製して文字を入れ替え** | 会社の決まったデザインに合わせられる | テンプレートの枠に内容を合わせる必要がある |

出典：Marp CLI のドキュメントと解説、Deckary・Open Design の比較記事（ツールを販売している会社の記事なので割り引いて読む）。

## このスキルの結論：「構成を先に固め、PowerPointに直接作る」

1. **構成（ゴーストデッキ）を文章で作る**：結論タイトル・図解の型・事実の置き場所。ここで内容の合意を取る。
   コンサルタントがデザインの前にタイトルだけで資料を組むのと同じ手順。
2. **PowerPointに直接生成する**（`deck_kit.js`）：受け取った人が自分で編集でき、Excelの表も同じ内容から作れる。
3. **画像とPDFで確認する**（`render.sh`）：スマホでも確認でき、PowerPointと同じフォントで改行位置まで確かめられる。
4. **同じ内容から必要な形式を出す**：
   - 発表用 → `.pptx`（動き付き）
   - 配布用 → `.pdf`（動きなしの最終状態）
   - 数字の一覧・集計 → `.xlsx`（`references/excel.md`）

HTMLでの下書きは、Web公開が目的のとき（アーティファクトのページなど）だけ使う。
PowerPointが最終形なら、HTMLを経由すると変換で崩れ、作業も二重になる。

## 1つの資料で複数の形式が必要なとき
- 正本は1つ（生成スクリプトか、表のデータ）。PowerPointとExcelで数字を二重に手入力しない。
- 表の数字はExcelを正本にし、PowerPointには結論と主要な数字だけを載せ、出典として「詳細：○○.xlsx」と書く。
- 投影用を完成させてから、配布用は「動きを外す・ノートの要点を本文に足す」で作る（別に作り直さない）。
