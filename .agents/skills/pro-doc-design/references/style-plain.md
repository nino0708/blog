# style: "plain"：緑1色の濃淡 × 白地 × ゴシック

ユーザーの指摘を重ねて作った、**装飾を控えめにした既定のスタイル**。
- 「飾りすぎ（cloud）」→ 色は1色の濃淡、雲・回路・影はやめる
- 「飾らなすぎも殺風景」→ 表紙と締めの雲と回路、左端の縦帯、本文右下の薄い雲だけ残す
- 「明朝の見出しがキモい」→ 書体は全部ゴシック（Noto Sans JP＋Inter）
- 「色をシンプルにしたら見にくくなった」→ **濃淡の役割を決めて、配置で見せる**（下の「濃淡の使い分け」「配置の型」）
- 「背景はクラウドを表す雲と IT の模様を少し」→ 表紙と締めに同系色の雲・回路・ドット、本文は右下にごく薄く

骨組み（帯のタイトル＝目次の項目名、その下に POINT の一文）は cloud と同じ。
見本：`examples/sample_plain.js`。部品：`deck_kit.js` の `style: "plain"`、背景：`scripts/plain_art.js`。

```js
const d = kit.createDeck({ size: "A4", style: "plain", footer: "資料名", title: "資料名" });
```

## 濃淡の使い分け（ここがいちばん大事）
1色だけで見やすくするには、**面の濃さに役割を決め、守る**。

| 段 | 見た目 | 役割 | 1ページに |
|---|---|---|---|
| 0 蛍光ペン | 黄色い線（`d.marker`） | **一番伝えたい数字・語句** | **1か所まで** |
| 1 濃い面 | `accent1`（または `accent4`）＋白い文字 | 構造の目印：締めの帯・分類のラベル・主役の区分 | 1か所まで |
| 2 淡い緑の面 | `accent5`＋黒に近い文字 | ひとまとまり：背景・基本の数字・1位の型・POINT | 1〜2か所 |
| 3 灰の面 | `lt2`＋灰の文字 | 比べる相手（「以前のやり方」など）・休憩など重要でないもの | 必要なときだけ |
| 4 白＋細い枠 | 白＋`D3DDD8` の枠 | ふつうの中身（カード・表・行） | いくつでも |

- **文字は黒に近い灰（`text1`）**。緑の文字は「数字・番号・小見出し・参照（→ P.5）」だけ。本文を緑にしない。
- **大きな数字**（71%、411回、約7割）は `accent1` で大きく。これが色の代わりの主役になる。
- 濃い面を並べない。締めの帯（濃い）があるページでは、その上のカードは淡い面にする。
- 「分析」「補足」は濃い面にせず、**白＋左の緑の線（0.07インチ）**にする。
- 順位や番号を丸で囲んで並べない（丸が並ぶと重い）。2位以下は緑の数字だけ。主役（1位）だけ丸。
- 表の見出し行は淡い面（`d.head` が自動）。区分の列は「主役の区分＝濃い／もう一方＝淡い」（`d.cat` は淡い色なら文字を緑にする）。
- 濃い面の上で強調したい語は `accent3`（淡い緑）か白。淡い面・白の上では `accent1`。

## 強調は蛍光ペン（1ページ1か所）
緑1色だけだと「どこを強調したいのか分からない」と言われた。差し色・白抜きと見比べて、ユーザーは**蛍光ペン**を選んだ。

- 一番伝えたい1か所（数字か短い語句）の**下半分に黄色い線**（`#FFE07A`）を引く：`d.marker(slide, { x, y, h, fontSize, bold, phrase, prefix?, align?, full?, boxW? })`
- 文字の幅は実際の書体で測る（`d.measure` → `jp_wrap.py --measure`）。線は**文字より先に**描く（後ろに回すため）。
- 線を正確に置くため、強調する行は**1行ずつ別の文字枠**にする（複数行の段落の途中には引けない）。行の前半を `prefix` に渡すと、その幅だけ右にずらす。中央そろえは `align: "center"` に `full`（行全体）と `boxW`（枠の幅）。
- 濃い面の上には引かない（黄色が濁る）。強調したい所が濃い面にあるなら、その面を淡い面に変えてから引く。
- 蛍光ペンを使うページでは、他の強調（濃い面の工程・太字の緑など）を減らす。主役は1つ。
- 使った場所の例：71%、411回、約7割、「その中身を数字と型で整理した。」、「間違ってたら指摘して」、2番目の工程名、「一番時間がかかる」、「最初から全部わかっていなくて大丈夫です」。

## 配置の型（色を足さずに見やすくする）
色を変えるだけでは「再構成」にならない。**要素の並べ方そのもの**を内容に合わせて選ぶ。
共通：箱を減らして余白と罫線で区切る／主役は1つ・大きく左上／量と順位は棒の長さで見せる。

| 内容 | 配置 | 例 |
|---|---|---|
| 背景・導入 | 上に背景を大きな文で数行（要点だけ緑の太字）＋メタ情報を1行。罫線の下に「分かること」を横3列（上に緑の太線、Q番号を特大） | SAP P.3 |
| やり方・手順が主役 | 上に手順のステップ（主役の工程だけ濃い面）、下に比較（左＝灰の面で控えめ、右＝白＋上に緑の線） | SAP P.4 |
| 1つの数字が主役 | 左半分に特大の数字（120pt）＋内訳の帯＋分析を小さく。右に補助の数字（淡い面の2×2）とグラフ | SAP P.5 |
| ランキング・件数の比較 | **横棒の表**：順位／名前＋キーワード／棒（1位だけ濃い、他は淡い）＋回数／例。行は罫線で区切り、1位の行だけ淡い面 | SAP P.6 |
| 会話・やり取り | チャット風：左に番号と見出し、右に吹き出し（淡い面＋左の小さな三角）、最後の答えだけ濃い面 | SAP P.7 |
| くり返し・サイクル | 円の上に工程の白い箱を3つ、間に進む向きの三角、円の中に「くり返す」 | SAP P.8 |
| 次の行動・まとめ | 左に縦の番号リスト（罫線区切り、最後だけ淡い面）、右に縦長の締めの帯（`closingArt` に `x`,`w`） | SAP P.9 |
| 条件で分かれる対応 | 根元の箱（淡い面）から枝分かれする線 → 分類ラベル → 対応 | 運用 P.5 |
| 一覧＋気づき | 主役の表を上に、気づきは下に淡い面で小さく | 運用 P.6 |
| 魅力＋道のり | 魅力はアイコン＋2行の2×2一覧（罫線区切り）、道のりは1本の線に番号の丸（最後だけ塗る）＋下に説明 | 運用 P.7 |
| 時間の配分 | 帯を大きく（高さ1.5）。主役の帯に時間を書き添える（「日による 3時間」） | 運用 P.4 |

## 部品の違い（cloud との差）
- `cloudCover`：濃い緑の地＋同系色の雲・回路・ドット。`motif` は無視。
- `toc`：色の面を使わず、左に部の名前＋縦線、項目は罫線で区切った行。
- `chips`：淡い緑の面。`callout`：淡い緑の面＋濃いラベル（文字は黒、強調は `accent1`）。
- `timelineBar`：主役（`vary`）だけ濃い緑、決まった予定（`fixed`）は淡い緑、休憩（`rest`）は灰。
- `roadmap`：淡い → 濃いへ段階的に（進むほど濃く）。
- `closingArt`：表紙の絵を切り抜いた濃い帯。`x`,`w` を渡して縦長にすると、右側（雲）を切り抜き、文字を上に置く。

## 書体
- 全部ゴシック：和文 Noto Sans JP、英数字 Inter。見出しも同じ（`headFont` は指定しない）。
- 明朝はユーザーに不評。使わない。

## 納品前に見る所
- [ ] 濃い面が1ページ2か所以上ないか（締めの帯も1か所に数える）
- [ ] 本文の文字が緑になっていないか
- [ ] 淡い面の上に白い文字、濃い面の上に緑の文字が乗っていないか
- [ ] 主役（大きな数字か濃い面）が各ページで1つに決まっているか
- [ ] 隣り合う帯（POINT と題材など）が同じ見た目で並んでいないか（片方を白＋枠に）
